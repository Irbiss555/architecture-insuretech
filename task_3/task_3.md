
## Проблемы приложения
1. При каждом REST-запросе **ins-product-aggregator** последовательно опрашивает 5 компаний, скоро 10 компаний. Латентность ответа растёт линейно от числа компаний; любое «медленное» API блокирует всю цепочку
2. Периодический polling **core-app** (15 мин) и **ins-comp-settlement** (24 ч) к агрегатору - burst запросов к агрегатору и сторонним API, лишняя нагрузка.
3. Клиенты видят неактуальные цены, что влечет финансовые потери/жалобы; расчёт комиссий идёт по устаревшим данным.
4. Каскадные ошибки - падение одного внешнего API тянет вниз **ins-product-aggregator**, затем — **core-app** и **ins-comp-settlement** (отчёты).


## Решение
1. Сервис **ins-product-aggregator** переходит на push-модель. Периодически (или WebHook’ами) подтягивает тарифы из компаний, а затем публикует `ProductUpdated`-event в Kafka
2. Сервисы **core-app** и **ins-comp-settlement** подписываются на `ProductUpdated`. Данные приходят почти сразу.
3. Взаимодействие **core-app** и **ins-comp-settlement**. Тут используется **Transactional Outbox**: при успешном оформлении полиса **core-app** добавляет запись в таблицу **outbox_policy**, надёжно коммитится в той же транзакции, далее Debezium считывает и отправляет событие `PolicyIssued` в Kafka - ночной REST-pull не нужен.
4. Kafka как «шина» событий: топики: **product-updated**, **policy-issued**
5. Ошибки внешних API изолируются - проблемы со страховщиками не блокируют UI
6. При добавление новых компаний добавляется только новый Consumer-task в **ins-product-aggregator**, остальные сервисы не меняются.
